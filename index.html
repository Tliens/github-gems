New to GitHub? Start here

GitHub is just a place where people publish code and apps — mostly for free. Learn these nine words and 80% of any repo page makes sense:

StarBookmark itA free "I like this". The count is a rough quality signal — nothing more.
ForkCopy it to meYour own copy of a repo, to change freely without touching the original.
WatchSubscribeGet notified about activity. "Watching" ≠ starring — it's email-level attention.
IssueReport / askThe project's forum: bug reports, questions, feature wishes all live here.
PRPropose a changePull Request: "here's my fix" — the way code contributions get reviewed and merged.
CloneDownload the codeCopy the full project (with history) to your machine. You rarely need this as a user.
ReleaseThe download pageReady-to-use versions with installers or binaries — what you want as a non-coder.
READMEThe manualThe front page of a repo. Good projects explain install & usage here in plain language.
LicenseThe rulesWhat you may do with it. MIT/Apache-2.0 = use freely, even commercially.

3 quick checks before you trust any project

  1. Recent commits — open "Commits": activity in the last ~6 months means someone's home.
  2. Issues get answers — unanswered piles of issues from years back = likely abandoned.
  3. A real license — no license technically means "all rights reserved". Gems here always have one.

FAQ

What counts as a "gem" here?

Projects with 1,000–30,000 GitHub stars, actively maintained (updated within 24 months, not archived), with a real working product you can use today — and quality far above their fame.

Why the 1k–30k star range?

Below 1k stars quality is hard to guarantee; above 30k a project is usually already famous and doesn't need discovering. The sweet spot is where quality is proven but the project is still under-known — especially in the Chinese-speaking community. When a listed gem outgrows 30k stars, it earns a 🎓 Graduated badge and stays on the list.

Are the star counts accurate?

Every project was live-verified against the GitHub API on the date shown at the top of the page. Counts drift over time, so treat them as an approximate snapshot.

How do I submit a gem?

Open an issue on the GitHub repository with the project link and why it deserves a spot. Submissions are reviewed by hand before being added.

Why are famous projects listed too?

The 🏆 Legend projects are the famous pillars — React, Linux, VS Code and friends. They are listed so newcomers get their bearings and cross-field explorers can spot the landmarks of other fields; they are clearly badged and kept separate from the 1k–30k hidden gems the site is about.

I'm a complete beginner — where do I start?

Start with the "New to GitHub" section: it explains stars, forks, issues and pull requests in plain words, plus a 3-point checklist for judging any project. Then browse gems tagged "Ready to use" — downloadable apps that need zero coding.

The legend behind this site

封神传说 · Fengshen Legend

GitHub Gems (codename 封神传说 — "Investiture of the Gods") is a hand-curated discovery directory for open source: 💎 137 hidden gems live-verified from GitHub's 1k–30k star sweet spot, and 🏆 24 legendary projects as landmarks. Every star count is checked against the GitHub API — nothing guessed.

In the Chinese classic Investiture of the Gods, the sage Jiang Ziya fishes with a straight hook — not for fish, but for the worthy, whose names he writes onto the list that makes them immortal. That is our metaphor: underrated gems get seen, great works get crowned. A star is not the end; being discovered is.
